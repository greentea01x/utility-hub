The project

This is the entry point to the documentation set for a one-semester capstone project. Four documents, one PRD and this page describe a single web application completely enough to build it, design it, test it and defend it. Everything below is written in English; everything the product itself says to a user is written in Thai, because the users are Thai.

The short name UtilityHub at the top of the PRD is superseded by Juristic platform at the bottom of the same PRD and is deleted by D-01. The tenant, incidentally, sees neither name: the receipt letterhead carries only the apartment's own identity, and LINE messages are signed — นิติบุคคล {apartment_name}.

What the product does

Juristic Platform lets the juristic person of one apartment building bill each room, every month, for the three charges a tenancy actually generates — water, electricity and the common area fee — and for nothing else: it charges no rent and holds no lease data. Staff walk the building with a phone and type each room's water and electricity meter readings; the system subtracts last month's reading to get the units used, prices them at the rate in force for that period, and calculates the common area fee from the room's floor area multiplied by the rate per square metre. The three amounts become one monthly bill that the juristic person reviews and approves, after which the bill is delivered to the tenant through the apartment's LINE Official Account. When the tenant brings cash to the office, the counter confirms receipt in one action: the bill flips to Paid, a numbered receipt is issued and printed on A5 paper, and a confirmation message goes back out on LINE. Automatic reminders go out before the due date and after it, announcements are broadcast to selected floors, and a dashboard plus four reports show what was billed, what was collected, who is in arrears, and how much water and electricity each room has used over the past twelve months.

The documentation team

Four roles, four owners, four documents. Each owner is the only person who edits their document; anyone who needs it changed raises the change with the owner. Where two documents disagree, the precedence order is PRD → product decisions → engineering spec / UI design / test plan, and the losing document is corrected rather than worked around.

On the role titles

The titles describe the responsibility each author carried while writing, not a job the students hold. In a 3–4 person team one person routinely wears two of these hats; what must not happen is two people editing one document, or a document changing without its owner knowing.

Document conventions

Language

Documentation prose is English. Product UI copy — labels, buttons, badges, validation messages, LINE messages, the receipt — is Thai, verbatim, because the users are Thai. The English page identifiers the PRD uses survive in routes, filenames, payloads and test hooks: Login, Dashboard, Rooms, Tenants, Meter Reading, Monthly Billing, Bill Detail, Payment, Receipt, Announcements, Reports, Settings. The two never mix inside one string: the Monthly Billing page is บิลประจำเดือน on screen and /bills in every sentence that names a route.

Opening these files

The four documents are self-contained static HTML: no server, no build step, no dependencies to install. Double-click a file, or from this directory run open 01-product-decisions.html on macOS (xdg-open on Linux, start on Windows). Each page builds its own table of contents in the left rail from its headings, highlights the section you are reading, and follows your system's light or dark theme. All five documents live in the same folder, so the links on this page work from disk with no web server. The PRD is Markdown: open PRD.md in a text editor or any Markdown viewer. _shared/tokens.css is a stylesheet — read it in an editor; it is already inlined into 03, so nothing needs it to be loaded to view a mockup.

Diagrams need an internet connection

Every diagram in this set is Mermaid source inside <pre class="mermaid">, rendered in the browser by mermaid@11 loaded from the jsdelivr CDN, and the fonts come from Google Fonts the same way. Offline, the pages still open and every word is readable, but each diagram shows as its raw text and the typography falls back to a system font. Before presenting from a room with unreliable Wi-Fi, open each document once while connected so the browser caches both, or print to PDF in advance — the print stylesheet is part of the template and already drops the table of contents and avoids breaking a diagram across pages.

Printing

Every document prints with the sidebar removed and each h2 starting a new page; cards, callouts, tables and diagrams are kept off page breaks. Print to PDF for the defence hand-out rather than printing this page from a browser at the last minute.
