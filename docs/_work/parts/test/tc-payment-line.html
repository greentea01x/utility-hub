Payments, Receipts, LINE Notifications, Announcements & Reports

Sixty-nine executable test cases covering the money end of the system and every outbound channel: the cash counter and its receipt, the LINE Official Account (bill delivery, reminders, payment confirmation, announcements, account linking, webhook security and the notification log) and the four reports plus the history views. Every case is written against the db/seed.sql dataset of D-44 and the demo fixture ids of engineering spec §3.1.10, so a tester can run them in order without inventing data. Each row names the endpoint, the exact input, the exact expected output — status code, error code, Thai message, badge, stored value — and the requirements it discharges.

Priority

P0 demo-critical or money-touching. A red P0 blocks the PRD §28 demo path or can produce a wrong amount, a duplicate receipt or a message a tenant should never have received. All P0s run before every push and on the morning of the defence.

P1 required behaviour that a grader or the office will exercise, but whose failure does not corrupt money.

P2 polish, copy and non-blocking hints.

Type follows ADR §6.9's three tiers: unit (no database), API and e2e (integration, scratch schema, built-in fetch + the cookie helper), UI (rendered page or print sheet, asserted by hand or by data-* hook).

Three rules that decide whether a case is written correctly
  1. Assert the arithmetic, never the calendar (D-44). seed.sql computes every date from the run date. Any case below that quotes 5 ก.ย. 2026 or REC-202609-000852 is quoting a documentation value; the executable assertion is on due_date = MAX(due day, approval + 3 days), on REC-<payment month YYYYMM>-<6 digits>, and on 10 × 18 = 180 / 70 × 8 = 560 / 30 × 35 = 1,050 / total 1,790.00.
  2. Receipt numbers are unique and monotonic, not gapless (D-05 #10, D-27). No case asserts that sequence numbers are consecutive. A case that did would fail against the seed's starting offset before the application was even opened.
  3. Money format differs by surface (D-03). Tables, Bill Detail and the receipt render 1,790.00; LINE messages and sentence text render 1,790 บาท with the trailing .00 dropped. A case that asserts the wrong one on the wrong surface is a defective case, not a defect.

One continuous counter that never resets, allocated inside the payment transaction. The two assertions the project commits to are that no two receipts share a number and that a later payment never receives a lower one. Gaplessness is explicitly not claimed and must not be tested (D-05 #10).
