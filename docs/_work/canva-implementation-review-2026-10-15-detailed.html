UTILITYHUB / PROJECT REVIEWตรวจเมื่อ 15 ตุลาคม 2569

Canva × Implementation

ผลตรวจสไลด์ Canva
เทียบกับระบบที่พัฒนาปัจจุบัน

ทิศทางโครงงานและวิธีคำนวณค่าใช้จ่ายตรงกัน แต่สไลด์ยังปะปนข้อมูล MySQL เดิม ภาพแบบจำลอง และฟังก์ชันที่ยังพัฒนาไม่ครบ โดยเฉพาะ Tech Stack และการแจ้งเตือน LINE

ขอบเขต Canva 12 สไลด์ + ภาพ Tech Stack ที่ส่งมาโค้ดล่าสุด 16a20b9ผลทดสอบที่อ้างอิง 10 ต.ค. 2569

อ่านเนื้อหาผ่าน Canva และตรวจไฟล์โค้ดจริงในโปรเจกต์ รายงานนี้ใช้คำว่า “ยังไม่ยืนยัน” เมื่อไม่มีหลักฐานเรื่องบริการภายนอก และใช้คำว่า “ทำบางส่วน” เมื่อโค้ดยังไม่ครบตามภาพหรือขอบเขต ผลทดสอบ 36 รายการและเบราว์เซอร์ 6 สถานการณ์เป็นผลที่บันทึกไว้วันที่ 10 ต.ค. ไม่ได้รันใหม่ในการตรวจครั้งนี้

จุดที่ควรแก้ก่อนตรวจ Tech Stackข้อความพร้อมใช้ตรวจครบ 12 สไลด์งานที่ยังไม่ครบหลักฐาน
01 / ประเด็นสำคัญ

จุดที่ควรแก้ก่อนนำเสนอ

  1. 1
    เปลี่ยน MySQL ให้เป็น PostgreSQL บน Supabase ให้ครบทั้งชุด

    สไลด์ 6 เขียน Supabase แต่ยังใช้รูป MySQL และสไลด์ 10 ระบุ “MySQL Database” โค้ดปัจจุบันใช้ pg และ PostgreSQL ผ่าน Supabase Session Pooler จึงต้องแก้ทั้งรูปและชื่อฐานข้อมูล [หลักฐาน DB]

  2. 2
    ระบุ LINE ว่าอยู่ระหว่างพัฒนา

    มี webhook สำหรับผูกบัญชีและงานสร้างคิวเตือนใกล้ครบกำหนด/ค้างชำระแล้ว แต่ยังไม่มีการเรียกส่งข้อความ LINE จริง และการอนุมัติบิล/รับเงินยังไม่ได้สร้างข้อความแจ้งบิลหรือยืนยันชำระตามภาพ สไลด์ 9 ควรคงป้าย “แบบจำลอง” ให้ชัด [หลักฐาน LINE]

  3. 3
    เปลี่ยนภาพสไลด์ Staff ให้ตรงสิทธิ์จริง

    ภาพในสไลด์ 8 มีชุดปุ่ม “อนุมัติและส่งบิล” และ “ยกเลิกการชำระเงิน” รวมถึงฟอร์มชื่อผู้พักปะปนอยู่ ชุดองค์ประกอบเหล่านี้ไม่เหมาะใช้แทนหน้า Staff ซึ่งระบบจริงอนุญาตให้ดูห้อง จดมิเตอร์ และดูความคืบหน้าเท่านั้น [หลักฐานสิทธิ์]

  4. 4
    นำ Chart.js ออกจากรายการที่อ้างว่าใช้แล้ว

    ไม่พบ Chart.js ใน dependency, หน้าจอ หรือสคริปต์ของแอป กราฟในสไลด์ 7 เป็นภาพแบบจำลอง ส่วน endpoint ชื่อ /api/dashboard/charts ปัจจุบันคืนข้อมูลสรุปเดียวกับ summary ยังไม่ได้ทำกราฟตามภาพ [หลักฐานกราฟ]

  5. 5
    แยก GitHub, โฮสต์แอป, ฐานข้อมูล และตัวตั้งเวลาออกจากกัน

    แก้ “GitHup” เป็น “GitHub” และย้ายไปหมวดจัดการซอร์สโค้ด ระบุฐานข้อมูลเป็น Supabase ส่วน Render และ cron-job.org ให้ใส่เป็นแผนหรือรอยืนยันการใช้งานภายนอก Aiven ไม่ใช่ฐานข้อมูลที่ระบุในสถาปัตยกรรมปัจจุบัน จึงควรตัดออกหากไม่มีการใช้งานอื่นที่ยืนยันได้ [หลักฐาน Deploy]

สิ่งที่ตรงกันอยู่แล้ว: HTML/CSS, JavaScript, EJS, Node.js, Express, การทดสอบด้วย Node.js Test Runner และ Playwright รวมถึงกระบวนการจดมิเตอร์ สร้างบิล อนุมัติ รับเงินสด และเปิด/พิมพ์ใบเสร็จ ตัวอย่างห้อง 205 รวม 1,790.00 บาท ตรงกับการคำนวณในระบบและภาพ LINE [หลักฐานคำนวณ]

02 / สไลด์ 6

Tech Stack ถูกบางส่วน และควรจัดหมวดใหม่

ชื่อเทคโนโลยีหลักของเว็บถูกต้อง จุดที่คลาดเคลื่อนคือฐานข้อมูลในรูป รายการ Chart.js และการนำบริการที่ยังไม่ยืนยันมาอยู่ในหมวด “ใช้งานแล้ว”

ในสไลด์ผลตรวจสิ่งที่พบจากระบบข้อความ/การแก้ที่แนะนำ
HTML / CSSตรงEJS สร้าง HTML และโหลด public/css/app.cssคงไว้ใน Frontend / Web
Javascriptตรงแอปใช้ JavaScript และมีสคริปต์สำหรับพิมพ์ใบเสร็จแก้รูปแบบชื่อเป็น JavaScript
EJSตรงapp.js ตั้ง view engine เป็น EJS และมี template ของหน้าจอจริงใช้ “EJS สำหรับสร้างหน้าเว็บฝั่งเซิร์ฟเวอร์”
Chart.jsยังไม่ได้ใช้ไม่พบ dependency หรือการเรียกสร้างกราฟในแอป มีเพียงภาพออกแบบ Dashboard และ summary APIนำออกจาก Tech Stack ปัจจุบัน หรือย้ายไป “แผนพัฒนา Dashboard”
Node.js / Express.jsตรงกำหนด Node.js 24 และใช้ Express 5 ใน package.jsonระบุ Node.js 24 + Express 5 ได้
Database: Supabase
ภาพ: MySQL		รูปขัดกับระบบปัจจุบันใช้ PostgreSQL บน Supabase ผ่าน Session Pooler และไดรเวอร์ pgใช้ Supabase (PostgreSQL) และเปลี่ยนภาพ MySQL เป็น Supabase หรือ PostgreSQL
LINE Official Accountทำบางส่วนมีการสร้างรหัสผูกบัญชี รับ webhook ตรวจลายเซ็น และบันทึก LINE user IDคงไว้ใน “ระบบเชื่อมต่อภายนอก” พร้อมสถานะ “กำลังพัฒนา”
LINE Messaging APIยังไม่ส่งจริงยังไม่มี outbound request ส่งบิล เตือน หรือยืนยันชำระไปยัง LINE การ drain ปัจจุบันเปลี่ยนสถานะในฐานข้อมูลเท่านั้นอย่าอธิบายว่าแจ้งเตือนส่งถึงผู้พักได้แล้ว ให้ระบุว่ายังเหลือส่วนส่งข้อความ
Node.js Test Runner / Playwrightตรงมี unit/integration tests และ browser E2E จริงคงไว้ ระบุผล 36 tests + 6 browser scenarios พร้อมวันที่ทดสอบ 10 ต.ค. 2569
GitHup ในหมวด Deployชื่อ/หมวดควรแก้มี Git repository, remote ชื่อ origin และ workflow ใน .github ซึ่งเป็นเรื่องซอร์สโค้ดและ CIแก้เป็น GitHub แล้วแยกหมวด “จัดการซอร์สโค้ด”
Renderยังไม่ยืนยันเป็นแนวทางโฮสต์ในเอกสารเดิม แต่การอ่านโค้ดครั้งนี้ไม่ยืนยันว่ามี deployment ที่เปิดใช้งานจริงบน Renderระบุ “แผนโฮสต์แอป: Render” จนกว่าจะยืนยัน URL และ deployment จริง
Aivenไม่ตรง DB ปัจจุบันระบบที่ตั้งค่าและทดสอบไว้ใช้ Supabase PostgreSQL ไม่พบการใช้งาน Aiven ในเส้นทางเชื่อมต่อที่เอกสารปัจจุบันระบุตัดออกจากรายการปัจจุบัน เว้นแต่ยืนยันบทบาทอื่นที่ใช้อยู่จริง
cron-job.orgยังไม่ยืนยันมี endpoint POST /internal/jobs/daily และตรวจ job token แต่ไม่ใช่หลักฐานว่าตั้ง external scheduler แล้วแยกเป็น “ตัวตั้งเวลางานภายนอก: แผน/รอยืนยัน”

หลักฐานประกอบ: Stack, Database, Dashboard, LINE, Deployment

อย่าให้คำว่า Supabase สื่อเกินสิ่งที่ใช้อยู่: แอปใช้ Supabase เป็นบริการ PostgreSQL โดยล็อกอินผ่านระบบของ Express และเก็บ session ด้วย connect-pg-simple ไม่ได้ใช้ Supabase Auth หรือเรียก Data API จาก browser ในโค้ดปัจจุบัน

04 / ผลตรวจรายสไลด์

เทียบครบทั้ง 12 หน้า

คำว่า “วัตถุประสงค์” หรือ “ขอบเขต” ใช้บอกเป้าหมายโครงงานได้ แม้ยังทำไม่ครบ ความเสี่ยงคือการนำเป้าหมายหรือภาพแบบจำลองไปอธิบายเป็นผลที่เสร็จแล้ว

หน้าหัวข้อผลเทียบกับระบบสิ่งที่ควรแก้/อธิบายเพิ่ม
01ชื่อโครงงานทิศทางตรง

ระบบค่าสาธารณูปโภค/ค่าส่วนกลางและเป้าหมาย LINE ตรงกับโครงงาน

คงชื่อได้ แต่ไม่ควรใช้ชื่อเป็นหลักฐานว่า LINE ส่งได้แล้ว แก้ภาษาเป็น “แอปพลิเคชัน” และใช้ตัวพิมพ์ให้สม่ำเสมอ เช่น “Utility and Common Area Fee Management”
02ผู้จัดทำ/อาจารย์ที่ปรึกษาไม่ใช่ข้อมูลฟังก์ชัน

ไม่มีข้อขัดแย้งทางเทคนิคให้เทียบจากโค้ด

ให้ผู้จัดทำตรวจชื่อและรหัสตามข้อมูลจริง รายงานนี้ไม่ตรวจยืนยันตัวบุคคล
03ที่มาและความสำคัญเป้าหมายตรง สถานะยังไม่ครบ

การรวมมิเตอร์ บิล และการชำระเงินทำได้แล้ว ส่วนการแจ้งเตือนผู้เช่าผ่าน LINE ยังไม่ครบ

อธิบายว่าเป็นปัญหา/เป้าหมายที่ต้องการแก้ แล้วแยกส่วนที่ต้นแบบทำได้ปัจจุบัน ข้ออ้างเกี่ยวกับสถานประกอบการควรมีข้อมูลการสำรวจรองรับเมื่อใช้เป็นผลวิจัย
04วัตถุประสงค์ยังบรรลุไม่ครบทุกข้อ

มิเตอร์ คำนวณ บิล เงินสด ใบเสร็จมีแล้ว การจัดการห้อง/ผู้เช่าแบบครบวงจรและ LINE ยังทำบางส่วน

คง 7 วัตถุประสงค์ได้ แต่เพิ่มสถานะรายข้อ ระบุรายงานทางการเงินสำหรับ “ผู้ดูแลระบบ” ส่วน Staff เห็นเพียงห้องและความคืบหน้าจดมิเตอร์
05ขอบเขตการทำงานโค้ดยังไม่ครบตามขอบเขต

ยังไม่มีคอลัมน์ “ประเภทห้อง” การเพิ่ม/แก้ห้อง ผู้เช่า และอัตราบริการยังไม่ครบ หน้าตั้งค่าปัจจุบันอ่านข้อมูลเป็นหลัก

ตัด “ประเภทห้อง” หากไม่ต้องการเพิ่มจริง แยก CRUD ที่รอพัฒนาออกจากงานที่ทำแล้ว รายงานปัจจุบันมีลูกหนี้ค้างชำระ/CSV แต่ยังไม่ใช่ชุด Dashboard และประวัติทั้งหมดตามเป้าหมาย
06โปรแกรมที่ใช้มีข้อมูลคลาดเคลื่อน

รูป MySQL, Chart.js, Aiven และหมวด Deploy ไม่สอดคล้องกับสถานะปัจจุบันทั้งหมด

ใช้ข้อความในส่วน 03 ของรายงาน เปลี่ยนโลโก้ DB แก้ GitHup เป็น GitHub แยกโฮสต์/ตัวตั้งเวลา และติดสถานะ LINE
07แบบจำลองหน้า Adminเป็นแบบจำลองจริง

ภาพมีการ์ดข้อมูลและกราฟ แต่หน้า Dashboard ปัจจุบันเป็นคำต้อนรับและเมนู ยังไม่ได้แสดงหน้าตาตามภาพ

คงคำว่า “แบบจำลอง” ให้เด่น เพิ่ม “ยังไม่ใช่หน้าจอระบบปัจจุบัน” ถ้าต้องการอธิบายผลงานที่เสร็จ ให้ใช้ภาพจากตัวแอปจริงแทน [กราฟ]
08แบบจำลอง Staff phoneภาพปะปนบทบาท

ภาพองค์ประกอบ UI มีปุ่มอนุมัติ/ยกเลิกการชำระและฟอร์มชื่อผู้พัก ซึ่งไม่ใช่สิทธิ์ Staff ปัจจุบัน อีกทั้งปุ่มยกเลิกการชำระยังไม่มี flow จริง

ใช้เฉพาะหน้าจอห้อง/จดมิเตอร์/ความคืบหน้าสำหรับ Staff ย้ายชุดปุ่ม Admin และตัวอย่าง UI components ไปหน้าอื่น หากใช้ภาพมือถือให้แสดงหน้าจอมือถือจริง [สิทธิ์]

05 / ความคืบหน้าโค้ด

สิ่งที่นำเสนอว่า “ทำแล้ว” ได้ และงานที่ยังเหลือ

นำเสนอเป็นผลงานปัจจุบันได้ควรระบุว่าทำบางส่วน / ยังเหลือ
ล็อกอิน แยกสิทธิ์ Admin/Staff และเก็บ session ใน PostgreSQLจัดการผู้ใช้ผ่านหน้าจอ และงาน CRUD ห้อง/ผู้เช่า/อัตราบริการให้ครบ
บันทึกมิเตอร์ ตรวจเลขไม่ลดลง คำนวณหน่วยจากครั้งก่อนworkflow เปลี่ยนมิเตอร์ และส่งงานจดมิเตอร์เพื่อตรวจตามแบบจำลอง
สร้าง Draft คำนวณเงินด้วย PostgreSQL decimal และอนุมัติบิลย้อนอนุมัติบิลและแก้บิลตาม flow ที่กำหนด
รับเงินสด สร้าง Payment/Receipt และพิมพ์ใบเสร็จยกเลิกการชำระเงิน การนับการพิมพ์ และรายละเอียดใบเสร็จให้ครบตามแบบ
API สรุปข้อมูล และรายงานลูกหนี้ค้างชำระพร้อม CSVหน้า Dashboard แบบการ์ด/กราฟและรายงาน/ประวัติให้ครบตามเป้าหมาย
สร้างรหัสเชื่อม LINE รับ webhook และสร้างคิวเตือนตามวันกำหนดส่ง LINE จริง ข้อความแจ้งบิล/ยืนยันชำระ การกระจายประกาศ และยืนยัน scheduler ภายนอก
Audit ของการจดมิเตอร์ อนุมัติ รับเงิน ผูก LINE และสร้างประกาศใน transaction เดียวกันAudit ของฟังก์ชันที่ยังไม่พัฒนา การมีชื่อ action ใน schema ไม่ได้แปลว่ามี workflow นั้นแล้ว
ผลที่บันทึกไว้: 36 tests และ 6 browser scenarios ผ่านเมื่อ 10 ต.ค. 2569การทดสอบ LINE ภายนอก/UAT และการยืนยัน deployment ครั้งล่าสุด ไม่ได้รวมอยู่ในการตรวจรายงานนี้

ข้อมูลในโปรเจกต์ที่ยังไม่ตรงกัน: GitHub Actions

พบการตั้งค่า CI เดิมที่ยังอิง MySQL ใน .github/workflows/ci.yml:9–17 ยังใช้ service mysql:8.4 และ URL แบบ MySQL ทั้งที่แอปเปลี่ยนเป็น PostgreSQL แล้ว อีกทั้ง workflow ไม่ได้ตั้ง TEST_DATABASE_URL ตามชุด integration tests ปัจจุบัน จึงไม่ควรอ้างว่า CI บน GitHub ตรวจระบบ PostgreSQL ครบแล้วจนกว่าจะแก้และตรวจผลรันจริง [หลักฐาน CI]

นี่เป็นข้อขัดแย้งที่พบจากไฟล์ตั้งค่า ยังไม่ได้เปิดดูหรือรัน GitHub Actions ออนไลน์ในการตรวจครั้งนี้ รายงานนี้ไม่ได้แก้ workflow หรือโค้ดแอป

ลำดับที่แนะนำ

  1. ก่อนนำเสนอ: แก้สไลด์ 6 และ 10 ให้ใช้ PostgreSQL เหมือนกัน จัดหมวดเครื่องมือใหม่ และปรับภาพ Staff หน้า 8
  2. ให้สถานะตรงกัน: ติดป้าย “แบบจำลอง” และ “กำลังพัฒนา” ให้ Dashboard, LINE และงาน CRUD ที่ยังไม่ครบ
  3. งานพัฒนาถัดไปตาม handoff: bill revert และ payment void พร้อมเหตุผลบังคับ/ตรวจสถานะ/บันทึก audit จากนั้นเดินหน้าส่ง LINE จริงและทำหน้าจอที่ยังเหลือ
  4. ก่อนอ้างว่า Deploy/CI พร้อม: ยืนยันบริการโฮสต์และตัวตั้งเวลา แก้ workflow ให้ตรง PostgreSQL แล้วตรวจผลรันจริง
